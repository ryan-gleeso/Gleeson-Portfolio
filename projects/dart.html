DART

Drone Assisted Remote Treatment — a simulated drone fleet that searches for wildlife and coordinates a response under human supervision.

ROS 2 Gazebo LiDAR Thermal Sensing Obstacle Avoidance RViz In Development

Why DART?

The project explores a wildlife-management concept for park rangers, conservation teams and wildlife authorities: using drones to locate animals across a forest and coordinate a targeted response.

Our proposal considers how remote monitoring could support field teams working across large or difficult-to-access areas. The intended application combines animal detection, location recording and operator-approved tagging or treatment.

For Robotics Studio 1 at UTS, we are developing this concept as a simulation. The focus is on robotic perception, navigation, coordination and operator interaction. Treatment is represented as a simulated mission action.

System overview

The baseline fleet consists of two search drones and one response drone operating in a custom Gazebo forest world. ROS 2 provides the software framework for connecting sensors, drone control and mission logic.

Search drones use downward thermal sensing to locate potential animals. A separate response drone is intended to approach a detected location, re-detect the target and capture an RGB image for the operator.

LiDAR and range sensors support obstacle detection and clearance control. The operator interface is intended to display mission progress, drone and animal locations, imagery and target status.

Planned mission workflow

  1. Select the search area. The operator defines the region to search through the mission-control interface.
  2. Distribute search paths. Search drones receive routes covering the selected area.
  3. Detect and locate a target. Thermal sensing identifies a potential animal. The search drone centres above it and shares an approximate location.
  4. Check for previous detections. Mission logic checks the target record to avoid creating duplicate response tasks.
  5. Dispatch the response drone. The response drone approaches the location while maintaining clearance from terrain and obstacles.
  6. Request an operator decision. RGB imagery supports identification. The operator can ignore the target or approve the simulated action.
  7. Record the outcome. The intended workflow updates the target's status and mission map, then continues the search.

This is the intended complete workflow. Final integration and repeated end-to-end testing remain part of the development plan.

Human-in-the-loop control

Operator involvement is a central part of DART. Drone sensing provides information, while the operator makes the identification and response decision.

The planned interface brings together target imagery, drone locations, mission progress and animal status. It also provides mission controls for continuing the search or returning drones to their origin.

Automated species identification is a stretch goal. Operator identification from RGB imagery remains the primary approach for the current project.

LiDAR and clearance control

The sensor architecture includes 360-degree LiDAR for surrounding obstacle detection and downward ranging for altitude control.

The response drone also includes upward ranging for overhead clearance and camera-aligned ranging intended to support target localisation.

At the September progress review, LiDAR obstacle detection and downward ranging were implemented. Upward ranging had basic logic integrated, while camera-aligned localisation logic remained outstanding.

Maintaining clearance over rapidly changing terrain is a key challenge. The development plan considers anticipatory altitude control to reduce reliance on late corrective movements.

Simulation and development tools

The team established a custom 100 × 100 m Gazebo environment containing terrain, a river, sparse trees and animal models.

A simpler development world supports isolated module testing before integration into the forest simulation. RViz and RQT help inspect sensor outputs, robot states, camera streams and transform frames.

The proposal established separate software packages for interfaces, simulation worlds, drone platforms and control logic. Multiple drone namespaces help separate each drone's communications within the ROS 2 system.

Scope and design decisions

The project scope was refined to prioritise a working search-and-response demonstration. Full 3D mapping was removed, with LiDAR focused on obstacle avoidance.

Human models and vehicle-based drone deployment were removed from the immediate scope. Moving animal models remain a stretch goal.

Environmental detail was reduced to manage computational load. The current forest uses light foliage, so performance in dense canopy remains a limitation to investigate.

Next development stages

  • Refine search-path generation and distribution between drones.
  • Prevent duplicate responses to previously detected animals.
  • Integrate response-drone navigation and altitude control.
  • Connect RGB imagery to operator identification.
  • Integrate mission-control displays and commands.
  • Complete repeatable end-to-end mission testing.

Planned evaluation considers search coverage, detections, response navigation, image delivery and accurate target status recording. These are demonstration objectives, rather than completed performance results.

Longer-term vision

The proposal imagines extending the concept into a broader wildlife-monitoring platform, combining animal locations, population maps and treatment records.

Future research could explore moving-target tracking, automated species identification and coordination between aerial and ground robots. These ideas sit beyond the current semester's simulation scope.
